05 Roadmap

迭代路线：先 MVP 闭环，再做复杂资产化

第一阶段只验证一个问题：用户愿不愿意为可信的诊疗方案付款，老用户真实反馈能不能提高购买信任，订单拆账能不能形成可解释、可合规、可运营的长期返佣机制。

看行动计划 Slides 下一章：合规安全

分润权二级市场和区块链，是后续版本的第二个故事，不是 MVP。

1. 阶段总览

阶段 目标 核心交付 判断标准
MVP 0.1 讲清楚商品和分润。 新版 PRD、故事版 Slides、关键规则确认、低保真原型。 总裁能判断比例、规则、结算周期。
MVP 1.0 跑通购买和分润闭环。 方案商城、订单支付、老用户反馈、分润台账、后台审核。 至少 3-5 个方案、真实订单、真实老用户池。
V1.1 增强运营效率。 B 端代理人、推荐人看板、客服工单、财务导出、异常冻结。 运营团队能低成本维护老用户和渠道。
V1.2 增强分润公平性。 老用户质量分、时间窗口、最近 N 名、方案分层费率。 老用户池不被无限稀释，作弊率可控。
V2.0 探索分润权资产化。 分润权转让、买断、收益预测、合规审计。 能明确法律属性和交易边界。
V3.0 探索数据资产能力。 脱敏数据集、授权管理、可信计算、数据交易所适配。 已完成专项合规论证和外部合作。

2. MVP 0.1：决策准备

文档改写

把“微生态健康数据资产交易平台”改成“疑难病诊疗方案商城”，统一对外口径。

规则确认

确认 70/15/10/5 拆账比例、老用户池均分、T+7 结算和退款冻结。

原型验证

画出用户买方案、看反馈、提交反馈、看收益的核心页面。

合规预审

让法务先看“返佣、推荐、老用户池、代理人服务费”的边界。

3. MVP 1.0：4-6 周开发计划

周次 产品与设计 研发 运营准备
第 1 周 确认 PRD、信息架构、关键页面原型。 搭建项目、用户体系、方案表、订单表。 确定首批方案运营方和方案清单。
第 2 周 方案详情页、购买页、老用户反馈页。 实现商城列表、方案详情、支付下单。 收集老用户反馈模板和审核规则。
第 3 周 收益看板、后台审核、订单状态设计。 实现反馈提交、审核后台、订单履约状态。 培训客服和医学审核人员。
第 4 周 分润账单解释、异常状态文案。 实现分润引擎、钱包流水、冻结和结算批次。 跑第一轮内部模拟订单。
第 5 周 根据试用反馈补交互和文案。 退款回滚、风控冻结、财务导出、日志。 组织小范围真实用户试点。
第 6 周 上线清单、帮助中心、用户协议。 修复问题、部署、监控、备份。 正式冷启动和数据复盘。

4. MVP 1.0 必须验收的闭环

1

方案可售

运营方能上架至少 3 个真实方案。

2

用户可买

新用户能完成支付并看到订单状态。

3

反馈可审

老用户能提交反馈，后台能审核入池。

4

分润可算

完成订单能生成推荐人和老用户池收益。

5

账单可解释

用户、运营、财务看到同一套流水。

5. V1.1：运营增强

  • B 端代理人工作台：代理绑定、代提交反馈、服务费台账。
  • 推荐人工作台：链接、订单、佣金、退款冻结。
  • 客服工单：订单争议、服务投诉、收益疑问、材料补充。
  • 财务导出：批次报表、税务信息、付款状态、失败重试。
  • 风控规则：同设备刷单、异常推荐、批量虚假反馈预警。

6. V1.2：分润规则增强

当老用户池扩大后，均分可能导致单人收益过低，激励下降。V1.2 可以引入更细规则，但要保持可解释。

增强规则 解决的问题 注意事项
最近 N 名老用户 避免大池子无限稀释。 N 的取值要提前公示。
最近 N 月有效反馈 保证反馈新鲜度。 不能让早期贡献者突然失去预期。
质量阈值 提高反馈可信度。 审核标准必须透明。
方案分层费率 高客单、高履约成本方案需要不同拆账。 订单页必须明确显示规则。

7. V2/V3：后续探索

分润权二级市场

老用户可选择长期拿返佣，也可一次性把未来收益权转让给投资者或平台。

链上凭证和审计

当收益权可转让时，链上记录才有更明确价值，用于权属、转让、审计。

医疗数据资产化

在授权、脱敏、伦理审查、数据出境、交易规则全部清楚后，再启动专项模块。

路线图原则：不要让 V2/V3 的故事绑架 MVP。先证明方案能卖、老用户反馈能提升转化、分润能被用户和财务理解。
