02 Business Model

商业模式：新订单养活方案、推荐和老用户池

商业模式不是“患者把原始数据卖给买家”。更清楚的表达是：用户购买诊疗方案、消费即形成健康数据资产，方案运营方获得履约主收入，平台从订单中划出一部分作为推荐佣金和老用户的数据资产收益，让真实反馈持续带来后续收益。

看拆账 Slides 下一章：技术架构

电商类比：方案运营方是商家，老用户是高质量评价者，新用户是买家。

1. 商品到底是什么

标准诊疗方案包 方案说明、适用人群、检查建议、用药/治疗路径、复诊计划、服务权益。 医生、医院、专病团队或方案运营机构。 是，作为第一版主商品。
方案随访/管理服务 阶段随访、指标记录、康复指导、复诊提醒、客服协助。 方案运营方和平台运营团队。 是，可作为方案包的一部分。

2. 建议的订单拆账模型

以 ¥100 订单为例，MVP 可先用固定比例跑通闭环，后续再做不同品类、不同机构、不同渠道的差异化费率。

70% 方案运营方
15% 推荐人 R
10% 老用户池
5% 平台
分账对象 金额示例 业务含义 MVP 规则
方案运营方 ¥70 履约主收入，用于医生/机构服务、医疗资源和售后。 订单完成后可结算；退款时按规则回滚。
推荐人 R ¥15 直接带来新用户的人或渠道。 只认一层推荐关系；没有 R 时可进入老用户池或平台营销池。
老用户池 ¥10 奖励为该方案提供真实疗效反馈的人。 第一版建议均分；后续再加质量权重和时间窗口。
平台 ¥5 系统、支付、风控、客服、内容审核和规则治理。 平台抽成保持克制，优先证明生态可跑通。

3. 老用户池怎么成立

准入条件

  • 用户在平台购买过该方案或由 B 端代理录入有效服务记录。
  • 服务状态达到可评价节点，例如完成首疗程、复诊或随访。
  • 提交有效反馈材料，平台完成审核。
  • 明确授权使用脱敏摘要作为方案背书。

MVP 分配方式

第一版建议简单均分：订单完成时，将老用户池金额分给该方案下所有有效老用户。

均分不是最终最优，但它最容易解释、最容易验算，也最适合第一版验证。

后续增强

当订单和老用户规模变大，可增加简单权重：消费金额大小、用户由谁（B 端/C 端）介绍进来、最近 N 名、最近 N 月、反馈质量分、疗效可信度、复购贡献等。这是一个简单算法，不是复杂的贡献权重表。

4. B 端代理人的商业位置

B 端代理人不是多级分销者，更像“代运营服务商”。它帮助不擅长使用 App 的患者完成注册、资料整理、反馈上传、收益查看和提现。

代理事项 价值 收益方式 边界
代办注册和授权 降低老人、农村患者的参与门槛。 按协议从被代理老用户收益中收服务费。 必须留存授权记录，用户可撤销。
整理反馈资料 提高老用户池质量，减少无效内容。 服务费建议从老用户收益中抽取，例如 10%。 不能伪造疗效，不得承诺固定收益。
协助收益结算 让低数字能力用户真正拿到收益。 代理服务费单独记账。 不拿推荐链下级收益，不做多层抽佣。

5. 团队规划

产品负责人

明确商品边界、角色关系、订单状态、分账规则、后台审核流程和总裁待决策项。

业务拓展

签约首批方案运营方，拿到可售方案、服务承诺、价格和履约负责人。

医学审核

审查方案适用范围、禁忌、风险提示、反馈材料和夸大宣传。

运营与客服

组织老用户反馈、处理订单售后、维护社群、解释分润账单。

技术团队

建设商城、支付、订单、分账、钱包、审核后台和风控日志。

法务财务

确认返佣合规、隐私授权、税务扣缴、支付通道、代理协议和争议处理。

6. 总裁需要先拍板的三件事

  1. 分润比例：是否先按 70% 方案运营方、15% 推荐人 R、10% 老用户池、5% 平台试运行。
  2. 老用户池规则：MVP 是否采用均分，是否设置“有效老用户”的准入门槛。
  3. 结算周期：是否采用 T+7 或每周清算，退款期内收益先冻结。
结论：分润分的不是“数据被卖掉后的钱”，而是“新订单中为获客和可信背书预留的利润池”。这句话需要在所有产品、销售和融资材料中保持一致。
